# AR-IMMS Glossary

This glossary defines product terms used across AR-IMMS documentation.
Definitions are written for business analysts, developers, and other project contributors.

| Term                        | Definition                                                                                                                                                                                                                                                                                   |
| --------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Asset**                   | An infrastructure item represented in AR-IMMS. It may be a physical item, such as a Node or Rack, or a logical item associated with the infrastructure, such as a Workload.                                                                                                                  |
| **Node**                    | A computer that hosts or supports monitored workloads. In the PoC, a laptop or PC represents a Node.                                                                                                                                                                                         |
| **Rack**                    | A logical or physical grouping used to organize Nodes by their infrastructure location. In the PoC, a physical rack may be represented by a model or another simplified setup.                                                                                                               |
| **Workload**                | An application or service group running on one or more Nodes. In the PoC, a containerized application and its database represent a Workload.                                                                                                                                                 |
| **Service**                 | A component of a Workload that performs a distinct function or communicates with other components. A database may also be treated as a Service when describing Workload monitoring.                                                                                                          |
| **Telemetry Agent**         | Software associated with a Node that collects or receives monitoring data and sends it to the monitoring system. It is a system actor, not a human user.                                                                                                                                     |
| **Exporter**                | A component that exposes monitoring data about a Node or another monitored target for collection.                                                                                                                                                                                            |
| **Monitoring data**         | Measurements or signals used to understand the observed state of a Node, Workload, or Service.                                                                                                                                                                                               |
| **Monitoring completeness** | An indication of whether the expected monitoring data for an asset is being received. It describes the availability of monitoring data, not the asset’s actual health.                                                                                                                       |
| **Fresh monitoring data**   | Monitoring data received recently enough to be considered current under the applicable monitoring rules.                                                                                                                                                                                     |
| **Node monitoring state**   | A summary of how completely a Node’s expected exporter data is being received: **HEALTHY** means all expected exporters are reporting, **DEGRADED** means only some are reporting, and **NO DATA** means none are reporting. These states describe monitoring coverage, not hardware health. |
| **Alert**                   | A signal raised when monitoring rules detect a condition that may require attention. An alert may contribute to an Incident but is not itself the full incident-management record.                                                                                                           |
| **Incident**                | A recorded operational condition that requires investigation, tracking, or follow-up. An Incident can be related to an affected Asset or Workload.                                                                                                                                           |
| **Maintenance activity**    | Work performed to inspect, verify, prevent, or address an operational condition, with its outcome recorded for later reference.                                                                                                                                                              |
| **Preventive maintenance**  | Planned work intended to identify or reduce potential problems before they cause an Incident.                                                                                                                                                                                                |
| **Corrective maintenance**  | Work performed in response to an identified problem or Incident.                                                                                                                                                                                                                             |
| **Asset identification**    | The process of confirming which registered Asset a user is interacting with, for example by scanning its QR code.                                                                                                                                                                            |
| **Augmented reality (AR)**  | An interface that presents digital information in the user’s view of the work site, associated with the Asset being identified or inspected.                                                                                                                                                 |
| **Digital twin**            | A digital representation of infrastructure and its relationships. The PoC may use simplified representations and does not imply a complete, real-time replica of a production data center.                                                                                                   |
| **AI-assisted analysis**    | Analysis or suggestions produced from available operational evidence to support a user’s assessment. The user remains responsible for decisions and actions.                                                                                                                                 |
| **Proof of concept (PoC)**  | A limited implementation used to demonstrate selected AR-IMMS capabilities and evaluate the product approach within the constraints of the testbed.                                                                                                                                          |

## Naming Notes

- Use **Node** for a monitored computer; do not use it as a synonym for an individual Service.
- Use **Workload** for the application or service group running on infrastructure; use **Service** for one of its components.
- Use **Alert** for a monitoring signal and **Incident** for the operational record that users investigate or track.
- Use **monitoring completeness** or **monitoring state** when describing whether expected data is arriving. Do not use these terms as a claim that the underlying hardware is healthy.
- Use **Telemetry Agent** for the software associated with a Node, and **Exporter** for a component that exposes monitoring data.
